Chaos run report

Open-source demo with a fictional support-reply workload and a deliberately unreliable fake provider (timeouts, 429 with Retry-After, 500 and slow replies). Seed 42, 40 requests, 4 workers, up to 5 killed mid-call, spending cap $0.0420 (illustrative prices). Rerun with python -m chaos.run --seed 42.

Both sides get the same client requests (same headers, same repeated POSTs) and the same fault rates. The naive side has no idempotent API and no safeguards in the worker, so each row says which half is responsible. Which worker gets killed, and when, depends on timing, so counts can move a little between runs. The checks in the "With safeguards" column must pass on every run (the script exits non-zero otherwise).
